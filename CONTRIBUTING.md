# Contributing

Tom de Base is a research prototype. Changes should preserve a clear distinction between measured/computed values and product heuristics.

## Local setup

The deployed page has no build step.

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000` and allow camera access.

For automated tests, use Node.js 20+:

```bash
npm test
```

## Before opening a pull request

- run `npm test`;
- test the camera path in a secure context;
- avoid changing color equations without adding/updating reference tests;
- document any new external runtime dependency;
- do not add API keys, tokens or user images to the repository;
- keep accuracy claims consistent with `VALIDATION.md`.

## Change boundaries

Prefer small, reviewable changes.

Recommended sequence for the architecture refactor:

1. color-science modules;
2. calibration state;
3. camera/orientation handling;
4. MediaPipe adapter;
5. application-progress heuristics;
6. UI rendering.

Do not combine a numerical color-math change with a large UI redesign unless there is a clear reason.

## Testing numerical changes

For CIEDE2000 or Lab conversion changes, use published reference values rather than snapshots generated by the implementation under test.

For camera/calibration changes, add empirical test notes or fixtures where possible and explain what capture assumption changed.
